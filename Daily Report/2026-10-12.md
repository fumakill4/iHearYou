# Daily Report — 12 October 2026

Created by **i729**. Signature: i729.

## iHearYou 1.2.0 changes

- Microphone and speaker/headphone devices can be selected while the microphone is active. The session restarts with the chosen devices; an active WAV recording is saved and continues in a new file.
- The device list uses input/output capabilities, active-device status, and USB/Bluetooth/Continuity connection labels. Hidden/private engine devices and the app's own loopback are excluded. Automatic refresh runs every two seconds, with a manual refresh button also available.
- Losing an active device stops the session and displays a message. The app also detects a device with the same UID receiving a new CoreAudio ID.
- An optional Safari receiver streams audio over the local network to the iPhone's built-in speaker. It provides a QR code, copy-link action, connection status, volume, a meter, and Disconnect. This mode uses a Mac, USB, or Bluetooth microphone; Safari on the same iPhone is not combined with Continuity input.
- The app icon was replaced using **Real app logo.icns** directly. The signature remains i729, and the credit reads **Created by i729**.
- The full app-and-driver installer, app ZIP, separate driver installer, and checksums were published on GitHub Releases. Distribution uses the i729 identity and excludes recordings, local configuration, logs, personal paths, and Finder metadata.

## Verification and limits

The release build succeeded, and the bundled icon was byte-identical to the supplied ICNS file. The full installer was expanded to check payload locations, versions, and local app/driver signatures. The app binary contained none of the personal name/path markers checked.

The iPhone microphone appeared as a Continuity device; USB and wireless modes were observed in the macOS list. Local capture produced a 48 kHz mono WAV with nonzero signal. Device disconnection stopped the session with a message. Bluetooth testing requires a physical Bluetooth device, which was not connected during these checks.

Safari on the Mac successfully received the app stream for more than 40 seconds. The final build sent 144,000 finite mono PCM samples at 48 kHz in a three-second probe. The probe ran with quiet input and contained zeros, so it was not used as evidence of speech output. The server rejected incorrect paths (404), uploads (405), and a second receiver (409). The user then opened the Safari receiver on a physical iPhone, spoke into the Mac microphone, and confirmed that **sound was audible on the iPhone**. The Mac browser recorder and DSP pipeline use the same engine as the previous version; the new receiver receives processed PCM audio.

Changing the speaker selection from Mac speakers to DisplayPort during recording kept the microphone session active, saved the old WAV, and continued in a new WAV. Both checked files contained audio frames in valid 48 kHz mono format. Output was restored to the Mac speakers with physical monitoring off; Safari speaker mode remained active following the user's test.

Receiver audio is sent over local HTTP without transport encryption. The mode is off by default, the random link is valid only during activation, and buffering/backpressure is bounded. The iPhone Safari tab must remain open with the screen on. Ad-hoc signing is not Apple Developer ID signing or notarization.

## iHearYou 1.3.0 — English/Indonesian and recording controls

Created by **i729**. Signature: i729.

- All first-party repository documentation is now in English. The requested implementation disclaimer was removed from README and third-party notices; required upstream attribution and licenses remain.
- Settings → Appearance → Language offers English and Bahasa Indonesia. Native controls, menus, window titles, tooltips, accessibility labels, recording dates, notices, and errors use the selected language. The preference is saved immediately. A normal new installation defaults to English.
- Browser recorder and iPhone Safari receiver start in the application's selected language and have their own language selector. Switching language preserves recording/listening state; unavailable browser storage is handled.
- Record audio can now start the microphone from an idle state. Its icon changes from a record circle to a red Stop square and its action becomes Save recording. Saving closes the WAV writers and refreshes the library.
- The library refreshes when opened, shows its saved recording count, exposes recording-folder errors, and offers a visible Stop microphone action for playback. Recordings are reachable directly from compact controls and their menu. Native WAV files remain in Music/iHearYou; browser-only recordings are downloaded through the browser.

Verification: release build and eight DSP tests passed. Focused localization checks covered message pairs, locale selection, existing-notice translation, and 1,000 concurrent accesses. Both web scripts passed syntax and live-language state tests. Native UI testing confirmed Record → Save/Stop → Record, preservation of 16 existing WAV pairs, a newly saved approximately 44-second pair, and clean-recording playback. Indonesian labels and selection remained after an explicit quit/relaunch. Public app and expanded full installer passed strict local signature, identity, icon, localization-resource, privacy, ZIP metadata, and SHA-256 checks.

Distribution: [iHearYou 1.3.0](https://github.com/fumakill4/iHearYou/releases/tag/v1.3.0) contains the complete PKG, Apple Silicon application ZIP, driver-only PKG, and checksums. Signing remains ad-hoc; the installer is not Apple-notarized. No recordings, local preferences, receiver URLs, or personal installation identity are included in the public payload.
