# Daily Report — 12 Oktober 2026

Dibuat oleh **i729**. Signature: i729.

## Perubahan iHearYou 1.2.0

- Mikrofon dan speaker/headphone dapat dipilih saat mikrofon aktif. Sesi dimulai ulang dengan perangkat yang dipilih; WAV yang sedang direkam disimpan dan dilanjutkan di file baru.
- Daftar perangkat memakai kemampuan input/output, status hidup, serta label USB/Bluetooth/Continuity. Perangkat internal atau loopback sendiri dikecualikan. Refresh otomatis setiap dua detik dan tombol manual tersedia.
- Hilangnya perangkat aktif menghentikan sesi dan menampilkan pesan. Pergantian UID yang sama ke ID CoreAudio baru juga dideteksi.
- Speaker bawaan iPhone mendapat penerima Safari melalui jaringan lokal, sesuai pilihan pengguna. QR, salin tautan, status koneksi, volume, meter, dan Putuskan tersedia. Input untuk mode ini adalah mikrofon Mac/USB/Bluetooth; Safari pada iPhone yang sama tidak digabungkan dengan Continuity.
- Ikon aplikasi diganti memakai **Real app logo.icns** secara langsung. Signature dan kredit tetap **Dibuat oleh i729**.
- Installer lengkap berisi aplikasi dan driver, ZIP aplikasi, installer driver terpisah, serta checksum disiapkan untuk GitHub Releases. Distribusi memakai identitas i729 dan mengecualikan rekaman, konfigurasi lokal, log, path pribadi, serta metadata Finder.

## Verifikasi dan batas

Build release berhasil dan ikon dalam bundle identik byte dengan ICNS yang diberikan. Installer lengkap diekstrak untuk memeriksa lokasi payload, versi, serta signature lokal app dan driver. Binary aplikasi tidak memuat penanda nama/path pengguna yang diperiksa.

Mikrofon iPhone terlihat sebagai perangkat Continuity; mode USB dan nirkabel teramati pada daftar macOS. Capture lokal menghasilkan WAV mono 48 kHz dengan sinyal nonzero. Hilangnya perangkat menghentikan sesi dengan pesan. Pengujian Bluetooth membutuhkan perangkat Bluetooth fisik yang belum tersambung selama pemeriksaan.

Safari Mac berhasil menerima stream dari aplikasi selama lebih dari 40 detik. Build final mengirim 144.000 sampel PCM mono 48 kHz yang finite dalam probe 3 detik; probe dilakukan saat input tenang dan isinya nol, sehingga tidak dijadikan bukti ucapan. Server menolak path salah (404), upload (405), dan penerima kedua (409). Pengguna kemudian membuka penerima Safari pada iPhone fisik, berbicara ke mikrofon Mac, dan mengonfirmasi **suara terdengar di iPhone**. Perekam browser Mac dan pipeline DSP memakai engine yang sama seperti versi sebelumnya; receiver baru menerima PCM bersih setelah pemrosesan.

Pergantian pilihan speaker Mac → DisplayPort saat merekam mempertahankan sesi aktif, menyimpan WAV lama, dan melanjutkan ke WAV baru. Kedua file hasil pemeriksaan memiliki frame audio serta format mono 48 kHz yang valid. Output dikembalikan ke speaker Mac dengan monitor fisik mati; mode speaker Safari tetap aktif sesuai pengujian pengguna.

Audio penerima dikirim melalui HTTP lokal tanpa enkripsi transport. Mode mati secara default, tautan acak hanya berlaku selama aktivasi, dan buffer/backpressure dibatasi. Tab Safari iPhone harus tetap terbuka dengan layar menyala. Signature ad-hoc bukan Developer ID/notarization Apple.
